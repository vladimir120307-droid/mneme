# Бенчмарки

Числа ниже воспроизводятся командой:

```bash
python benchmarks/vector_search.py
```

Железо: Windows 11, Python 3.13, один поток (numpy-бэкенд не параллелит
matvec; нативный — через OpenMP — параллелит).

## Векторный поиск · numpy

`dim = 384` (как у `all-MiniLM-L6-v2`), `k = 10`, 100 запросов.

| N (векторов) | add (всего, мс) | search (среднее, мс) | QPS |
|---:|---:|---:|---:|
| 10 000 | 18 | 0.21 | 4 860 |
| 50 000 | 94 | 1.64 | 609 |
| 100 000 | 183 | 3.20 | 312 |

`add` — O(1) амортизированно благодаря буферу с удваиваемой ёмкостью:
вставка 100k векторов стоит ~180 мс, а не ~10 минут.

## Про нативный бэкенд

Когда `mneme._native` собран (через `python -m mneme.build_native`),
тот же brute-force алгоритм гонится на C++17 с авто-векторизованным
SIMD-циклом и OpenMP-параллелизмом по рядам. Python-обёртка не добавляет
существенного оверхеда — числа имеют ту же форму, но с меньшей константой.

CI на свежем раннере публикует свои цифры артефактом в job `native`.

## Когда менять бэкенд

- **< 100k векторов:** numpy достаточно; <5 мс на поиск = сотни QPS
  на одном потоке.
- **100k – 1M:** native даёт чистый множитель сверху.
- **> 1M:** имеет смысл HNSW (`pip install "mneme[fast]"`) — sub-linear
  поиск ценой приближённости.

## Как масштабируется скоринг

Гибридный скоринг-ядро (`_hybrid_score` в `memory/store.py`)
векторизовано по K кандидатам, которые возвращает индекс. Если native
доступен — диспатчится в `_native.compute_scores`. End-to-end задержка
`MemoryStore.search()` упирается в поиск, не в скоринг, при K до
нескольких сотен.
