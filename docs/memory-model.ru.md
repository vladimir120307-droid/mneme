# Модель памяти Mneme

Mneme заимствует архитектуру памяти из когнитивной науки. Есть четыре
вида памяти, у каждого свои правила удержания, извлечения и обновления.
Именно это разделение позволяет агенту оставаться согласованным неделями
и месяцами, а не забывать всё на границе контекстного окна.

## Обзор

```
                       ┌────────────────────┐
                       │   Working memory   │  ← текущий диалог, эфемерная
                       └─────────┬──────────┘
                                 │ flush
                                 ▼
   ┌────────────┐  consolidate  ┌────────────┐
   │  Episodic  │ ─────────────▶│  Semantic  │  ← долгосрочное знание
   │   memory   │               │   memory   │
   └─────┬──────┘               └────────────┘
         │                              ▲
         │ extract                      │
         ▼                              │
   ┌────────────┐  patterns / how-to   │
   │ Procedural │ ─────────────────────┘
   │   memory   │
   └────────────┘
```

## Рабочая память

Краткосрочный буфер в контекстном окне модели во время диалога.

- Хранит последние N ходов (настраивается, по умолчанию 20).
- Эфемерная: гасится с концом сессии, если не промоутили.
- На каждом ходу значимые записи помечаются для перехода в эпизодическую.

## Эпизодическая память

Конкретные события: «юзер сказал X в дату Y», «тулза Z вернула эту ошибку»,
«договорились использовать стек W». Каждый эпизод привязан к timestamp
и источнику.

- **Поля:** `id`, `content`, `embedding`, `created_at`, `last_accessed_at`,
  `access_count`, `importance` (0..1), `source` (user / tool / self), `tags`.
- **Извлечение:** vector similarity + бонус за свежесть + бонус за важность
  + бонус за частоту обращений. Формула — в `mneme.memory.retrieval`.
- **Угасание:** эпизод с низкой важностью, к которому давно не обращались,
  становится кандидатом на удаление.

## Семантическая память

Обобщённые, time-independent факты, выделенные из эпизодов. «Юзера зовут
Владимир». «Юзер предпочитает короткие ответы по-русски». «Проект X
использует Postgres».

- **Поля:** `id`, `statement`, `embedding`, `confidence` (0..1), `support`
  (список episodic id, которые её родили), `updated_at`.
- **Источник:** строится только консолидатором, никогда не основным
  агентом. Это поддерживает чистоту семантической памяти.
- **Конфликты:** при противоречии оба факта остаются, старый помечается
  как superseded; агент видит свежий, в историю при желании можно
  заглянуть.

## Процедурная память

Как делать вещи. Сохранённые навыки, скрипты, последовательности тулзов,
workflows.

- **Поля:** `id`, `name`, `trigger` (когда применять), `steps`,
  `tools_used`, `success_rate`.
- **Источник:** добавляется пользователем явно, либо извлекается из
  эпизодов консолидатором, когда тот видит повторяющийся успешный
  паттерн.

## Консолидация («сон»)

Периодически (или по запросу) Mneme запускает фоновый проход:

1. **Promote.** Значимые элементы рабочей памяти становятся эпизодическими.
2. **Generalise.** Кластеры связанных эпизодов превращаются в
   семантические факты.
3. **Pattern.** Повторяющиеся успешные последовательности действий
   становятся процедурными навыками.
4. **Forget.** Эпизоды с низкой важностью, к которым давно не обращались,
   удаляются. Семантические факты, которые ими подтверждались, либо
   сохраняют другую поддержку, либо понижаются в confidence.

Консолидация работает в worker-потоке с небольшим бюджетом LLM-вызовов
на цикл, поэтому её можно гонять непрерывно.

## Извлечение во время запроса

Когда юзер шлёт сообщение, Mneme собирает контекст так:

1. Рабочая память (verbatim, последние N ходов).
2. Top-K семантических фактов по `similarity * confidence`.
3. Top-K эпизодов по композитному скору выше.
4. Любой процедурный навык, чей `trigger` сматчился с запросом.

Модуль ретривала следит за общим бюджетом токенов и отсекает кандидатов
с самым низким скором, пока не уложится. Отобранные куски складываются в
system-сообщение и идут в модель.
