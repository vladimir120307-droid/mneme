# Вклад в Mneme

Спасибо, что думаешь помочь. Mneme достаточно компактен, чтобы за один
вечер можно было реально сдвинуть его вперёд.

> 🇬🇧 English version: [`CONTRIBUTING.md`](CONTRIBUTING.md)

## Базовые правила

1. **Открывай issue до большого PR.** Несколько строчек согласования
   избавляют от переделки потом.
2. **Не раздувай поверхность.** Mneme = библиотека + CLI + REST,
   всё. Фичи, не служащие всем трём, обычно сюда не подходят.
3. **Тесты + ruff зелёные** до ревью.
4. **Без тяжёлых зависимостей** без веской причины. Сначала чистый
   Python и numpy, потом нативное ускорение, в последнюю очередь —
   сторонние БД/облака.

## Окружение

```bash
git clone https://github.com/vladimir120307-droid/mneme
cd mneme
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest
ruff check src/ tests/ benchmarks/
```

Опционально — C++ ядро (drop-in быстрее):

```bash
pip install pybind11
python -m mneme.build_native
```

## Как предлагать изменение

1. Fork → новая ветка от `master`.
2. Сделай изменение. Коммиты сфокусированные; один логический шаг —
   один коммит.
3. Прогон тестов и линтера локально.
4. Открой PR. Title в императиве («Add foo», «Fix bar»). Тело — *почему*;
   *что* — в диффе.
5. CI прогонит матрицу тестов и парити нативного ядра. Если красное —
   чинить тебе до ревью.

## Стиль кода

- Python 3.10+. Современные тайп-хинты (`list[str]`, `X | None`).
- Конфиг ruff в `pyproject.toml` — источник истины. Не обходи.
- Без комментариев, описывающих *что* делает код, — только неочевидное
  *почему*.
- Без print-отладки в дифф.
